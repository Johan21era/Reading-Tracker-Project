# Bedrock Master Plan — 2026-10-24

**Program:** Bedrock — erase the bug/glitch backlog, wire the dormant intelligence, fix every shipping blocker, and rebuild the data layer for the next several years.

**Status:** PLAN FOR OWNER REVIEW. No code has been changed by this plan.

**Execution model:** dedicated worktree/branch, one phase at a time, one **gate** at the end of each phase. The owner reviews the gate and replies **APPROVE**, **APPROVE WITH CHANGES**, or **STOP**. Nothing advances without approval.

## 0. The decisions this plan is built on

These are now declared decisions, not assumptions. If any is wrong, say so before Gate 0.

| ID | Decision | Consequence |
|---|---|---|
| **D-001** | **Local-first distribution.** The app is for you and a friend, installed from a GitHub release, not the Mac App Store yet. | Ad-hoc signing + `.dmg`/`.zip` + Gatekeeper instructions. App Store constraints still respected (sandbox, privacy manifest, clean bundle) so the path stays open. |

| **D-005** | **Keep all reading history forever.** | No age-based pruning. Add indexes, orphan cleanup, WAL, backups, and `VACUUM`/retention hooks. SQLite can handle millions of page timings. |

| **D-009** | **macOS 26.5 only; always target the current frontier.** | No compatibility back-ports or availability guards for older macOS. CI must use an Xcode 27/macOS 26 image. |
| **D-010** | **Delete true debris; quarantine future scaffold.** | ~1,700 LOC of verified debris is deleted; any genuinely future code is moved outside the app target with a manifest, not left compiling silently. |
| **D-011** | **Dedicated worktree/branch.** | `main` stays at the last green baseline. Work happens in a Bedrock worktree; merges happen only at approved gates. |
| **D-012** | **Swift 6 language mode + strict concurrency at the end.** | Gate G7 flips the compiler settings and fixes fallout; this is part of “strongest setting possible.” |
| **D-013** | **Interim app icon generated by us.** | A clean book/night-sky icon clears the packaging blocker now; final artwork can replace it later. |
| **D-014** | **Apple Silicon assumption for the first distribution.** | The embedded Python runtime is `aarch64`. If your friend has an Intel Mac, tell me now; we will need a second runtime + universal build, which changes G2B/G7 estimates. |

### Non-goals for this program

- No Mac App Store submission, notarization, or auto-update framework (path stays open).
- No CloudKit/iCloud sync.
- No iOS/iPad app.
- No AI/LLM features or network services beyond Open-Meteo.
- No social features.
- No pruning of reading history.
- No visual redesign beyond the new surfaces (Book Details, notes, collections, advanced context).

## 1. Definition of done

The program is done when all of these are true:

1. **Build:** Debug and Release both build clean on macOS 26.5/Xcode 27.
2. **Census:** full unit + UI suite green; all new defect pins green.
3. **Data:** the real 29.6 MB library migrates to SQLite with zero loss; a rollback rehearsal restores the JSON build.
4. **Scale:** launch loads summaries only; a reader opens a book lazily; analytics use SQL; performance budgets in §7 are met.
5. **Weather:** a real session writes an Open-Meteo snapshot; denied location shows an honest paused state; no silent default city.
6. **Context:** importing a library produces a meaningful V3 report without waiting for a live session; both context surfaces work; evidence persists.
7. **Library:** genre/series/word count populate at import; Book Details edits; notes (plain/Markdown/highlights/quotes) and collections survive relaunch and archive round-trip.
8. **Mirage:** built app contains a verified, signed runtime; in-app analyze works on a real EPUB; clean teardown; app still works with Mirage off/absent.
9. **Debt:** verified debris deleted/quarantined with a manifest; Swift 6 language mode builds.
10. **Distribution:** Release `.dmg`/`.zip` launches on a clean macOS user account after one documented Gatekeeper step.
11. **Truth:** README, registers, handoff, roadmap, tests, and new ADRs match the code.
12. **Owner signoff:** Gate G8 accepted.

```text
G0  Baseline & safety

 │
G4  Weather that works (Open-Meteo, location honesty, unified store)
 │
G5  Library intelligence (import metadata, Book Details, notes/highlights, collections)
 │
G6A Behavior Context V3 engine + evidence persistence
 │
G6B Behavior Context UI (simple panel + Advanced Context window)
 │
G7  Debt retirement, Swift 6, repo cleanup
 │
G8  Final acceptance, test hardening, docs truth, release package
```

Why this order:

- **G1 before architecture** removes live data bugs that would otherwise contaminate migration fixtures.
- **G2 before architecture** gives you an installable baseline and proves the distribution path early.
- **G2B before G3** resolves the riskiest binary-packaging unknown before we invest in the data layer. It is independent of SQLite.
- **G3 before weather/notes/context** means those features write directly to the unified database instead of being migrated twice.
- **G6 after G5** lets the advanced context UI reuse the Book Details/notes patterns and the unified DB.
- **G7 after features** avoids Swift 6 churn while APIs are still moving.
- **G8 last** so acceptance reflects the real final state.

G2B can be swapped with G3A if you want the data layer started first; the only dependency is “G2B before G8.”

## 3. Gate protocol (how you review)

At every gate I stop and produce:

```text
docs/plans/bedrock/gates/GATE-<id>.md
```

with:

1. **Scope delivered** — what changed and what did not.
2. **Commit range** — exact commits/tag; main untouched.
3. **Tests** — targeted pins, full census, new suites.
4. **Data receipt** — counts, checksums, migration/parity results.
5. **Performance receipt** — baseline vs new numbers.
6. **Manual evidence** — screenshots/recordings or a written clean-account rehearsal.
7. **Known issues / deltas** — honest, not buried.
8. **Rollback** — tag + exact command.
9. **Decision requested** — APPROVE / CHANGES / STOP.

You reply with one of those three. I do not proceed on silence. If you approve multiple gates in advance, I can run them back-to-back, but each gate still produces its receipt.

### Gate acceptance rules

- **Green census:** `191/0/4` baseline is the floor; new tests must pass. A gate with any failure is a STOP, not a “fix later.”
- **No test writes to real app-support data.** Gate 0 installs a guard; every gate verifies it.
- **No destructive migration without a copy.** JSON files are renamed `.migrated`, never deleted.
- **No half-migrated storage.** If G3B parity fails, we revert to G3A and keep JSON; we do not ship a lazy store with wrong analytics.
- **No silent feature degradation.** If weather/context/Mirage cannot work, the UI says so in plain language.
- **One finality per defect.** Each bug gets a Finality statement, a fix-log entry, and a named pin, per the house protocol.

### Phase G3 — Bedrock data layer (GRDB, full lazy, SQL analytics)

This is the largest phase. It is one program phase with **three hard sub-gates** so we never ship a half-migrated store.

#### G3A — SQLite foundation and migration parity

**Goal:** a real GRDB schema behind the existing DataStore public API, with JSON→SQLite parity, while still loading eagerly.

Deliverables:

1. Add **GRDB.swift** via SPM, pinned in `Package.resolved`.
2. `Core/Storage/LibraryDatabase.swift`:
   - `DatabasePool` with WAL, foreign keys, busy timeout;
   - all access through one owned database wrapper/queue;
   - no DB handle crosses threads;
   - schema migrations via `DatabaseMigrator`.
3. Schema v1 (initial; can evolve):
   - `meta(key, value)`
   - `books(id PK, title, author, file_url, file_type, total_pages, current_page, is_completed, date_added, genre, series, is_favorite, word_count_estimate, cover_path, bookmark_data, difficulty_profile_json, payload_json, created_at, updated_at)`
   - `sessions(id PK, book_id FK, start_time, end_time, start_page, end_page, audio_profile_id)`
   - `page_times(id PK, session_id FK, idx, page_number, start_time, end_time)`
   - `library_state(key PK, payload)`
   - `collections(id PK, name, date_created)`
   - `book_collections(book_id, collection_id, PK(book_id, collection_id))`
   - `notes(id PK, book_id FK, page_number, format, text, quote, locator_json, tag, created_at, modified_at)`
   - `achievements(id PK, kind UNIQUE, earned_at, book_id)`
   - `weather_snapshots(...)` (existing schema, unified)
   - `audio_profiles(id PK, session_id FK, payload_json)`
   - `behavior_events`, `application_sessions`, `inactivity_records`, `device_state_events` (created now, populated in G6)
   - indexes: `sessions(book_id)`, `sessions(start_time)`, `page_times(session_id)`, `page_times(start_time)`, `notes(book_id)`, `book_collections(collection_id)`, `weather_snapshots(timestamp)`, `behavior_events(timestamp)`.
4. `LibraryRepository` protocol + GRDB implementation.
5. Migration engine:
   - JSON/state/weather/audio → SQLite in one transaction;
   - count/checksum receipt;
   - idempotent;
   - JSON remains untouched (`.migrated` rename only at G3C).
6. DataStore storage flag: `storage.engine = json | sqlite`; default JSON in G3A. SQLite mode loads exactly the same `[Book]`/`LibraryState` eagerly for parity.
7. Parity harness: JSON vs SQLite on the real-store copy and synthetic fixtures:
   - book/session/page-timing counts;
   - every book field;
   - state, collections, achievements, notes;
   - archive export/import round-trip.
8. Crash tests: kill during migration/write; reopen; no partial data.

**Gate G3A acceptance:**

- SQLite mode produces the same public model as JSON on the real copy.
- Migration idempotent; JSON untouched; backup exists.
- Full census in JSON mode; SQLite parity suite green.
- No UI behavior change yet.

#### G3B — Full lazy loading + SQL analytics (the hard gate)

**Goal:** launch no longer loads 138k page timings; analytics come from SQL; readers load a book on demand.

Deliverables:

1. **Call-site inventory:** classify all `.sessions` (119) and `pageTimes` (34) accesses into:
   - summary-only (use cached columns),
   - reader/detail (load on demand),
   - analytics (SQL aggregate),
   - maintenance/Sentinel (SQL).
   No access is left ambiguous.
2. `DataStore` summary mode:
   - books load without sessions;
   - `sessionCount`, `totalReadingTime`, `lastReadDate`, `pagesRead` are cached columns;
   - `fullBook(id:)` / `sessions(forBookID:)` / `notes(forBookID:)` load on demand;
   - reader/notes/detail views show a loading state.
3. `AnalyticsSnapshot` + SQL store:
   - daily activity, totals, streak, reader profile, genre profiles, trend, time-of-day, per-book speed, session quality, improvement, predictions;
   - preserved synchronous public API where possible via an in-memory aggregate snapshot;
   - cache invalidated incrementally on mutation; no full re-scan.
4. Reader lazy-load path: PDF/EPUB opens, loads sessions for that book, page-turn writes are incremental SQL inserts.
5. Reports/Insights/Recommendations/Weather/BCE use SQL or snapshot APIs; no `books.flatMap(\.sessions)` hot paths.
6. Session history queries SQL with pagination.
7. Performance budgets:
   - warm launch < 1.5 s; cold launch < 3 s on the real library;
   - reader open < 500 ms;
   - page-turn save < 50 ms UI latency;
   - analytics dashboard cached < 100 ms, cold < 500 ms;
   - memory < 250 MB summary mode.
8. Parity harness extended to all analytics:
   - counts/sums exact;
   - derived values within 0.1% or documented tolerance;
   - random-book/session spot checks.

**Gate G3B acceptance:**

- Launch instrumentation proves page_times are not loaded at launch.
- All analytics/report/insight/recommendation/goal/achievement outputs match the JSON baseline within tolerance.
- Reader, notes, session history, export work.

## 9. Risk register and stop conditions

| Risk | Likelihood | Impact | Mitigation / stop rule |
|---|---|---|---|
| SQLite lazy parity breaks analytics | Medium-high | High | G3B parity harness; stop and revert to G3A/JSON if outputs differ |
| Real-data migration loses data | Low | Critical | Snapshot + transaction + count/checksum receipt + rollback rehearsal; stop on any mismatch |

| V3 produces misleading claims | Medium | High | DataMaturity gates, real timestamps, provenance UI; no claims without evidence |

| Mirage embedded Python fails sandbox/signing | Medium | High | Time-boxed G2B; fallback to honest dev-gated build; do not ship broken |

| Scope creep | Medium | High | Gates, non-goals, one finality per defect; owner approval per gate |
