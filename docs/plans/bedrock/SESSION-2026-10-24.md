## What changed

### Data safety / correctness
- Achievement award loop now inserts the awarded kind; one badge per kind.
- Loading `library-state.json` collapses legacy duplicates (earliest kept).
- Onboarding import uses the shared import path + duplicate rejection; goal
  editing merges instead of replacing the whole goal set.
- Spatial cards use the CoverStore-aware `coverImage`.
- PDF RSVP extraction is cancellable.
- PersistenceWriter submits jobs to the serial queue in call order; queue is
  the executor. `saveImmediately` drains real work.
- Crash-recovery sessions and Sentinel orphan repairs clamp to last page
  activity + 5 minutes.
- AnalyticsCache has a day bucket; dead `perBookSpeed` removed; Insights passes
  the real epoch.

### Test safety
- `RuntimeEnvironment` redirects test hosts and `--uitest` launches to a
  process-scoped temp store.
- `CoverStore.active` + `testOverride` keeps unit tests out of real covers.
- `SentinelEngine` accepts a journal URL; tests use temp journals.
- UI tests launch with `--uitest`.

### Release / packaging
- Generated 10-size app icon; `Assets.car` + `AppIcon.icns`.
- Added location entitlement; removed read-only/read-write conflict.
- Removed empty source `CFBundleIdentifier`.
- Shared scheme with non-parallel testables.
- `scripts/census.sh`, `verify-test-isolation.sh`, `benchmark.sh`,
  `package-release.sh`, `generate-app-icon.py`.
- Ad-hoc zip built in system temp (BUG-003-safe), with xattr stripping.
- Mirage runtime embedded by an Xcode build phase; nested interpreter/dylibs
  signed; smoke runs on a copy so `__pycache__` cannot invalidate the seal;
  production spawn passes `-B` and `PYTHONDONTWRITEBYTECODE=1`.

### SQLite foundation
- GRDB 7.11.1 pinned.
- `LibraryDatabase` with WAL, foreign keys, schema v1 (books, sessions,
  page_times, state, collections, notes, achievements, weather, audio,
  behavior tables, meta).
- Transactional import + synthetic round-trip + real-library parity.

## Next gate: G3B (the hard one)

G3B is the full lazy-loading + SQL-aggregate + DataStore switch. It is
deliberately not started in this session. It requires:

1. A call-site inventory of 119 `.sessions` and 34 `pageTimes` uses.
2. Summary-mode `DataStore` (`sessionCount`, totals, last read, pages read).
3. On-demand `fullBook(id:)` / `sessions(forBookID:)` for readers, notes, detail.
4. SQL aggregate APIs for analytics, reports, insights, recommendations,
   weather, achievements, and DataQuality.
5. A parity harness vs the JSON baseline, then performance budgets:
   warm launch < 1.5 s, reader open < 500 ms, analytics cached < 100 ms,
   memory < 250 MB.
6. Only then: real-store cutover, `.migrated` rename, rollback rehearsal.

Do not cut over the real store before G3B parity is green.
