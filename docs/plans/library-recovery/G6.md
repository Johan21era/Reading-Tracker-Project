Defects found by the new tests, fixed in this pass:

1. **Nested transaction in row repair.** `deleteOrphans` opened `db.inTransaction` inside `queue.write`, which already opens `BEGIN IMMEDIATE`. The export/delete path now runs with `writeWithoutTransaction` and one explicit transaction, so the export is durable before deletion and the delete is atomic.
2. **Foreign-key pragma inside a transaction.** `PRAGMA foreign_keys` is a no-op inside a transaction; undo could not restore orphan rows. The pragma now runs outside the transaction and is restored with `defer`.
3. **Read-only WAL inspection.** A WAL database without its `-shm` cannot be opened read-only; inspection falls back to a disposable private copy so the original is never opened writable.

## Owner acceptance script (copy the library first)

1. Quit the app. Copy the whole `Asterisma` data folder to `~/Desktop/Asterisma-acceptance`.
2. Launch. Open **Sentinel Health → Recovery**. Confirm the tab shows "Library is healthy" and the backup list when no incident exists.
3. Corrupt a *copy*: duplicate the data folder to a scratch location, truncate `library.sqlite3` mid-file, and point a scratch build at it. Confirm the app opens read-only, the launch card says recovery is in progress, and the header banner appears.
4. In Recovery, confirm: preserved file count, diagnosis rows, typed phrase required for restore, restore disabled without a verified backup.
5. Type the wrong phrase. Confirm nothing happens and the error key is shown.
6. Restore a verified backup with `RESTORE`. Confirm the receipt state, the data-loss estimate, and that the original exists as a pre-restore copy.
7. After recovery, open Sentinel and confirm a fresh deep cycle ran (History shows `recoveryVerified`, no probes ran while suspended).
8. Export the support summary and confirm it contains no file paths and no book text.
9. Return to the healthy copy and confirm the app opens normally, Sentinel resumes, and no incident is left behind.
